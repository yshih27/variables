# Executor WP — the long tail, frontend: every canonical page findable, titled as the question, described in data

Frontend executor, Varible. One PR fresh off `origin/main` (e.g. `feat/long-tail`), pushed, opened against main, NO merging. Own worktree with the three symlinks; `--webpack` for dev, but `next build` + `next start` for anything that exercises `revalidate` (a dev server never does); NEXT_PUBLIC_SHELL_V2=true; tsc/eslint/build clean; truthful trailer. ⚠️ `src/app/robots.ts` and `src/app/sitemap.ts` are changed by the orchestrator's cost-hygiene PR (`chore/cost-hygiene`: per-request pages to ISR, robots rules for the bulk crawlers and the personal pages, no false `lastModified`); if it is not merged when you start, stack on it with `--base chore/cost-hygiene` and say so in the body. Design: bet 4 in `docs/roadmap/features-roadmap.md`. The giants of collectibles data live in search; our answer to a search is a realized sale with a receipt, theirs is a listing. Nothing here computes a number: it makes the numbers we already publish findable and legible to a crawler.

## What exists (build on it, do not re-derive)
- Pages and their ONE read each: identity `/i/<slug>` (`getIdentityDetail`, 30 min; the page already derives `canonicalSlug` from the key); character `/ip/<ip>/characters[/<key>]` (`getCharacterDetail`; `readCharacterSearchRows` lists every character with its 30d volume; `hasCharacterExtractor` says which IPs have them); set `/ip/<ip>/sets/<set>` (`setIndicesFor`, `listSetIndices`); grades `/ip/<ip>/grades` (`listGradeIndices`); receipts `/index/<entity>/<month>` (`readIndexReceipts`, `entityIdFromPath`, `isReceiptMonth`); card `/card/<id>` (`getCardDetail`, `getCardMarket`). All read persisted snapshots; none builds anything on a request path, and this brief adds no read to any of them.
- The slug rules: `canonicalIdentitySlug`, `identitySlug`, `canonicalKeysOf` (`src/lib/card/identity.ts`, `src/lib/data/identityDetail.ts`). An alias slug (a v4.1 form, a superseded name) still renders and the proxy 301s it; `buildIdentitySearchRows` (`src/lib/data/identitySearch.ts`) excludes aliases with `canonicalKeysOf` so a card is offered once, at its one URL. The sitemap uses the same rule.
- `listIdentityIndex()` (slug → keys, slabs per key) and `cachedPanel()` (rows with `identity`, `ts`, `priceUsd`) are the two reads the identity sitemap needs. Both are in-process memos over gz snapshots (identity-index 2.0 MB, identity-slabs 5.2 MB, sale-panel 1.0 MB), so a sitemap route inflates them at most once a day, never per fetch.
- `metadataBase` is set in `src/app/layout.tsx` from `SITE_ORIGIN`; `generateMetadata` exists on every page above; share images exist for identity (`/api/og/identity/<slug>`), character, card, IP, platform, report and stats.
- Breadcrumbs: `src/lib/shell/crumbs.ts` (`crumbsFor(pathname, names, leaf)`) is the model the visible `Breadcrumbs` renders. The rail model `buildRailModel` (`src/lib/data/railModel.ts`; `RailNode`, `indexNode`) carries categories → IPs with `sets` per category and market-wide `grades`; `RailNav.tsx` renders the flyout lists `Sets` and `Grades · market-wide`; the palette's `PAGES` list lives in `CommandPalette.tsx`; `BottomTabs.tsx` is the mobile nav.
- Robots (after the cost-hygiene PR): `*` is disallowed `/api/`, `/status`, `/search`, `/vault/`, `/alerts`, `/watchlist`, `/*?`; the bulk AI and SEO-tool crawlers are disallowed everything; `sitemap` accepts a string array. Search engines proper keep the default rule: they are what this bet is built on.

## The surfaces
1. **The sitemap index.** The root `sitemap.xml` stays the static list (pages, IPs and their sub-pages, platforms and theirs). Three more, each a `sitemap.ts` under its segment with `generateSitemaps` (the file convention publishes `/<segment>/sitemap/<id>.xml`): `src/app/i/sitemap.ts` for identities, ids fixed at `0..3` (40,000 URLs per file, headroom under Google's 50,000 and 50 MB, room to 160K identities without a deploy; a file whose range is empty is an empty, valid sitemap), enumerating CANONICAL slugs only from `listIdentityIndex()` filtered by `canonicalKeysOf`, ordered by 30d sales then slabs so the first file is the liveliest, `lastModified` = the identity's last sale `ts` from the panel and ABSENT when it has none; `src/app/ip/sitemap.ts` for the character index pages and every character page (`readCharacterSearchRows`), every published set page (`listSetIndices`) and the grade index pages, `lastModified` = the rollups' `generatedAt`; `src/app/index/sitemap.ts` for the receipts page of every entity-month the price-index blob PUBLISHED (its `series` keys and points; never a held month), `lastModified` = the month's end. Every sitemap route exports `revalidate = 86400`, so the snapshots are inflated once a day for it; verify on `next build` that each is prerendered NON-EMPTY (the build reads the snapshots; an empty prerender would sit for a day). `robots.ts` lists all four sitemap URLs. No `/card/<id>` URLs: a slab is reached from its identity and is not the long tail's answer. A date this data does not carry is never written (`new Date()` is not a `lastModified`).
2. **Titles that are the question.** The `<title>` and `og:title` become the question a collector types, composed from the detail object; the `h1` stays the entity's name (a page is titled by what it is; the tag is how it is found). Templates, every slot from data: identity `What does a {name} ({set} #{number}) {grade} sell for? · VARIBLE`; character `Which {character} cards sell for the most? · {IP} · VARIBLE`; set `What do {set} cards sell for? · {IP} · VARIBLE`; receipts `How was {ticker} computed for {month}? · VARIBLE`. Card, IP, platform and list titles are unchanged. Over 60 characters, drop in this order: the ` · VARIBLE` suffix, then the `({set} #{number})` parenthetical, then edition and language; never the name or the grade. Descriptions (≤ 155 characters) carry the figures with their windows: identity `{n} realized sales across {k} venues since {first month}; the monthly Varible price with its n, the grade ladder, every slab, read from the chain.` and, for an identity with slabs and no sale yet, `No realized sale yet: {slabs} slabs across {k} venues and the grade ladder, read from the chain.`; character `{identities} cards and {slabs} slabs; 30-day resale by set and venue, the largest clears, and every identity's price.`; set and receipts in the same shape from their own detail. Beezie's machine is the Claw in any venue line; "tokenized collectibles", never "trading cards".
3. **One canonical URL per page.** `alternates.canonical` (absolute, via `metadataBase`) on every identity, character, set, grades, receipts, card, IP and platform page: the identity page's is its `canonicalSlug`, so an alias URL that still renders declares the card's one URL; every other page is self-canonical. `/search`, `/vault/<address>`, `/alerts` and `/watchlist` carry `robots: { index: false }` in metadata as well as in robots.txt (the file stops a crawl; the meta removes a URL that was already indexed). `/embed/*` keeps its `noindex` header.
4. **Structured data, from the page's own data.** One pure module, `src/lib/seo/jsonLd.ts`, unit-tested (`test:seo`), rendered as `<script type="application/ld+json">` per Next's guide (`JSON.stringify(...).replace(/</g, "\\u003c")`), types from `schema-dts` (dev dependency, types only): `Organization` + `WebSite` in the root layout (name, `SITE_ORIGIN`, `X_URL` as `sameAs`, the share mark as logo; no `SearchAction`, because `/search` is disallowed and the sitelinks search box is retired); `BreadcrumbList` on identity, character, set, receipts and card pages from `crumbsFor`, the same model the visible breadcrumbs render, so the two cannot disagree; identity `Product` (name, the share image, the description above, `category` the IP, `additionalProperty` for set, number, grade, edition and language) with `offers` as an `AggregateOffer` (USD, `lowPrice` the page's floor, `offerCount` the plausible asks, `availability` InStock, `url` the page) ONLY when the page itself shows a floor under its plausibility rule, and NO `offers` key otherwise: the Varible price is a realized statistic, never an `Offer`, never an `aggregateRating`, and a rich result is not worth an invented offer; character and set `CollectionPage` with `mainEntity` an `ItemList` of the leaderboard's identities (position, name, url); receipts `Dataset` (name `{ticker} {month}`, the method line as description, `temporalCoverage` the month, `creator` the Organization, `isBasedOn` the methodology page; a `distribution` only if a key-free URL serves the series, else none); card `Product` with its cert, grade and set as `additionalProperty` and `offers` only when the slab carries a plausible ask from `getCardMarket`. Every value in the JSON-LD is a value the page already renders; the test asserts that no figure appears in the markup that is not in the detail object.
5. **The chip that caches.** `/embed/price/<slug>` renders per request because its size and theme ride the query string (`?size=`, `?theme=`), and `searchParams` is request-time data a cached render cannot read; every venue page view that iframes a chip is a function invocation today. Move the variants into the path, `/embed/price/<slug>/<size>-<theme>` (the default `md-dark` at the bare slug), 301 the query form from `proxy.ts` (every snippet already pasted keeps working through the redirect), update "Get the chip" and the price payload's chip URL to the path form, and give the page the `generateStaticParams` export that makes its `revalidate` real. Verify on `next start`: the bare, the sized and the redirected URL each answer `s-maxage=1800` and a second hit `x-nextjs-cache: HIT`; an unknown size falls back to `md` rather than 404.
6. **Characters in the nav.** In the rail's Categories flyout, beside `Sets` and `Grades · market-wide`, a `Characters` list per IP that has an extractor (from `readCharacterSearchRows` in `buildRailModel`, the top rows by 30d volume, cached with the model), each row → `/ip/<ip>/characters/<key>`, an `All characters →` row → `/ip/<ip>/characters`; the same `Characters` link on the IP page header where `Sets` and `Grades` already sit; the palette's Pages group gains `{IP} characters`; the mobile More sheet lists it wherever it lists Sets. The rail's existing node grammar, no new colours, no client fetch.

## Constraints
Every page with a dynamic segment keeps its `generateStaticParams` export (added Sep 28; without it `revalidate` is a no-op and the page renders per request), and nothing new in a page or the layout reads `headers()`, `cookies()` or `searchParams`, which would make the whole tree dynamic again. No typed number anywhere: every n, k, month, count and price in a title, description or JSON-LD is read from the detail object the page already holds, with its window. Zero new reads on any page's request path; the sitemap routes read persisted snapshots once a day; the rail's characters ride the rail model's cache. ISR horizons unchanged. No client JavaScript added. Titles ≤ 60 and descriptions ≤ 155 characters by the drop order above, measured in the tests. "Tokenized collectibles", never "trading cards"; the Claw for Beezie; receipt lines, never banners. Nothing under `/embed`, `/vault/<address>`, `/search`, `/alerts` or `/watchlist` enters a sitemap or gains structured data.
