# Executor WP — the card name, backend: a name is never a grade

Backend executor, Varible. One PR fresh off `origin/main` (e.g. `fix/card-name-fallback`), pushed, opened against main, NO merging. Own worktree with the three symlinks; never write to production from an executor (`--out` modes, `SNAPSHOT_LOCAL_DIR`, dry runs and `--apply`-gated scripts only); tsc/eslint clean; truthful trailer. This is the name backfill the receipts page made visible (bet 1 follow-up); no migration.

## The defect, measured (2026-09-23, the live v4.2 identity index)
**568 identities carry a grade label as their card name** (one_piece 347 of 2,305 · basketball 169 of 857 · baseball 24 · football 11 · soccer 8 · yugioh 4 · pokemon 3 · other 2). Every slab behind them is a **Beezie** token. Their metadata has no name attribute at all — `normalizeTraits` reads `Card Name`, `Pokemon Name`, `Title/Subject`, `Player`, `Subject`, `Character`, and Beezie's non-Pokémon cards carry none of them; the name lives only in the token's `name`, in the shape **`<year> <set> <card name> #<number> <grade>`**:

```
2024 Memorial Collection Mr. 2 Bon Clay #EB01-061 PSA 10     Set Name=Memorial Collection · Card Number=EB01-061 · Grader=PSA · Grade=10 · Category=One Piece
2020 Panini Prizm Tyrese Haliburton #90 PSA 10               Set Name=Panini Prizm · Card Number=90 · Category=Basketball
2021 Topps Chrome Tarik Skubal #103 PSA 10                   Set Name=Topps Chrome · Card Number=103 · Category=Baseball
2020 Panini Obsidian Jordan Love #111 PSA 10                 Set Name=Panini Obsidian · Card Number=111 · Category=Football
```

So `cards.card_name` is null for them and `extractCardIdentity` (`src/lib/data/traits.ts`) falls back to the token name — and its fallback assumes Collector Crypt's shape, **`<year> #<number> <name> <grade>`** (`2010 #96 Magnezone-Holo PSA 8 He`): it takes "everything after the `#number` up to the grade". On Beezie's shape the text after the number IS the grade, and the lazy cut hands back `PSA 10` as the name. The identity index then keys `one_piece | memorial-collection | EB01-061 | PSA 10 | PSA 10` — a real card (set + number are right) with the wrong name — and the market receipts print a row called "Psa 10"; the One Piece character extractor nulls them (347 identities it cannot map); the price chip and API would headline "Psa 10 · PSA 10".

The name column is not wrong; it is empty. The read-time fallback is wrong. That is where the fix goes, and the two derived stores (the sale panel's identities and `cards.identity_key`/`identity_slug`) follow from it.

## Scope
1. **A shape-aware fallback, one function.** `src/lib/card/nameFromTokenName.ts` `cardNameFromTokenName({ name, set, number, grade }) → string | null`: find the `#number` token (or the row's number); take the segment **after** it up to the first grade label (`parseGrade` from `src/lib/card/grade.ts` is the SSOT for what a grade label is); if that segment is empty or is itself a grade label, take the segment **before** the number instead: strip a leading year, then strip the set as a prefix — the row's raw `set` string, else the normalised set's display name (`setDisplayName`), matched case-insensitively with punctuation folded — then trim. Never return a string `parseGrade` accepts as a whole; never return the set string alone; return null rather than guess. `extractCardIdentity` calls it in place of the inline cut, and keeps preferring the `card_name` column when present.
2. **The guard, at the key.** `identityKey` (and therefore `identitySlug`) refuses a `cardName` that is a grade label: the identity is null, the row is unpooled, exactly as a nameless row already is. A grade can never again be a name on any surface, whichever feed produces it.
3. **Unit table** in `src/lib/data/traits.test.ts` (`npm run test:names`): the four measured Beezie strings above; a Beezie one with a variant in the name (`2020 Panini Prizm Silver Tyrese Haliburton #90 PSA 10` → `Silver Tyrese Haliburton`, a different card and rightly so); a Japanese One Piece one (`… #OP05-002 BGS 10` with `Japanese` in the name → language lifted, name clean); Collector Crypt's shape (`2010 #96 Magnezone-Holo PSA 8 He` → `Magnezone-Holo`) and its name-before-number shape (`2023 Japanese Scarlet ex Klawf #88 CGC 10` → `Klawf`); a name with no grade in it; a name that is only year + set + number (→ null); the guard (`card_name = "PSA 10"` → null identity); a set-only name (→ null, not the set).
4. **The measurement, before any write.** Extend `scripts/backfill-card-identity-key.ts` with `--report-names` (dry, read-only): for every row whose current identity name is a grade label, the token name, the name the new fallback yields, and the platform; totals per platform and per IP; the 40 most-sold such identities with old → new name. This is the PR body's table, and it is how the 568 is confirmed against the column (expect: `card_name` null on all of them).
5. **The cutover pieces, unapplied.** Nothing new to run: after the merge and deploy, the next indices warm re-derives the panel through the fixed extractor (identities re-key on the real names; the receipts row becomes "Mr. 2 Bon Clay"; One Piece and sports characters map), and `scripts/backfill-card-identity-key.ts --rewrite --apply` re-keys `cards.identity_key`/`identity_slug` — the orchestrator runs both. The slugs that changed (`…/psa-10/psa-10` → `…/mr-2-bon-clay/psa-10`) are registered as aliases the same way the v4.1 slugs were, so the 568 old URLs keep answering and the API replies `canonical: false`.
6. **Report in the PR body**: the `--report-names` table (per platform, per IP, top 40 by sales); the character-mapping counts before → after for One Piece and the sports IPs (`SNAPSHOT_LOCAL_DIR` probe on a `--out` warm); the number of identities whose key changes; the unit table; timings unchanged (this is a pure function on a path that already runs).

## Constraints
No copy, no colours (not your lane). `parseGrade` is the only definition of a grade label; `setDisplayName`/`normalizeSetName` the only set knowledge; `identityKey` the only key. Zero production writes; the re-key is not applied by the executor. A name the function cannot recover is null, never the grade, never the set, never the whole token name.
