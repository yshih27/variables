# Executor WP — Renaiss, the sixth venue, backend: the first venue on BNB Chain, read from its own index API

Backend executor, Varible. ONE PR off `origin/main` (`feat/renaiss-venue`), pushed, opened against main, NO merging. Own worktree with the three symlinks; never write to production from an executor (`--dry-run` defaults, `--limit` caps, `--out=<dir>` for any blob, migrations as FILES the orchestrator applies); tsc/eslint clean; truthful trailer. Design: the Renaiss row under Now in `docs/roadmap/features-roadmap.md`; the data ask we sent on Sep 9 is beside this file (`renaiss-data-ask.md`). What changed since that ask: Renaiss's index API now publishes the venue's own marketplace sales and pack pulls, cursor-paged, with the cert and the card identity on every row. Three of the five venue legs come from this API alone; the other two (listings and floors, payout wallets) stay honest blanks with their reason, as Phygitals' secondary was.

## What exists (build on it, do not re-derive)
- **The API**, read Sep 30 (`https://api.renaissos.com/v1/openapi.json`; Swagger at `/docs`; every read is a `GET`, responses `Cache-Control: s-maxage=300`, permissive CORS): `GET /v1/renaiss/sales?after=&from=&limit≤500` (every marketplace sale on BNB Smart Chain, OLDEST first: `id` = `{txHash}:{logIndex}`, `blockNumber`, `soldAt`, `contract` = `0xF8646A3Ca093e97Bb404c3b25e675C0394DD5b30` (ERC-721), `tokenId` decimal string, `seller`, `buyer`, `currency` `USDT`, `price` decimal string, `priceUsdCents`, `slab { cert "PSA119571435", company, grade "10 Gem Mint" }`, `catalogCard { id, renaissItemId, name, setName, setCode, cardNumber, year, language, imageUrl }`; the seller fee is NOT in the row, it is on the `TradeExecutedV2` log the id names); `GET /v1/gacha/pulls?platform=renaiss&after=&from=&limit≤500` (pack checkouts, oldest first: `id`, `kind` `checkout|observed`, `machineId`, `machineName`, `pulledAt`, `buyer`, `checkoutId`, `transaction`, `pricePaid { amount, currency }`, `prizeValue { amount, currency }` = the PLATFORM'S STATED value, and the prize `tokenId` + `slab` + `catalogCard` + `imageUrl` once the platform names it — Renaiss V3 packs name it when the set sells out, so a trailing window is re-read). Paging: pass each response's `nextCursor` as `after` until `hasMore` is false, then keep polling with the last cursor; `from` (ISO 8601) starts at a time instead of the oldest row and is ignored when `after` is sent. Auth: `X-Api-Key` (`rk_…`) + `X-Api-Secret` (`rsk_…`); anonymous is **10 requests a day per IP** (a warmer must never run on it), a key is **10,000 a day**; every response carries `X-RateLimit-Limit/Remaining/Reset`, over is `429` + `Retry-After`. Images are served from `bhshyxmgzwogzgcf.public.blob.vercel-storage.com`.
- ⚠️ MEASURED Sep 30 on the anonymous tier: sales Sep 23–30 = 46 rows, $9,900, median $166, **46 of 46 linked to a cert and a card**, 33 buyers, 36 sellers, one contract, 38 Japanese / 5 English / 3 Simplified Chinese cards, PSA 10 on 42 (grade strings seen: `10 Gem Mint`, `9 Mint`, `GEM MT 10`, CGC `10 Pristine`); oldest sale 2026-01-09. Pulls: the first three hours of Sep 23 alone were 500 rows and more (`hasMore`), $14,740, 3 machines, 79 buyers, 500 of 500 named with a prize value; oldest pull 2025-11-06. Pulls dwarf resale; both are USDT.

## The build
1. **Registry.** `Chain` gains `"BNB Chain"`; `PlatformSource.key` and `CardPlatform` gain `"renaiss"` (code `rn`; `PLATFORM_META` label `Renaiss`; tsc will walk you to every `Record<CardPlatform, …>`); `PLATFORM_SOURCES` gains `{ key: "renaiss", name: "Renaiss", short: "RN", railCode: "RN", chain: "BNB Chain", vault: null, kind: "native", apiBase: "https://api.renaissos.com/v1", collectionAddress: "0xF8646A3Ca093e97Bb404c3b25e675C0394DD5b30", marketplace: <the contract that emits TradeExecutedV2, read off one sale's transaction on BscScan and cited in the comment> }`; `explorerUrlFor("renaiss", tokenId)` → `https://bscscan.com/nft/<contract>/<tokenId>`; the image proxy allowlist gains the exact blob host above. The board, the platform page, the rail and the coverage matrix then render Renaiss from the registry with "—" wherever no source exists.
2. **Client** (`src/lib/renaiss/client.ts`): the DYLI shape. Headers from `RENAISS_API_KEY` + `RENAISS_API_SECRET` (Actions secrets; no request path ever reads them). ⚠️ NO KEY, NO RUN: without both, every warmer exits 0 with one line saying so (the anonymous tier is 10 a day and a single run would burn it), so the step stays green until the key lands. Log `X-RateLimit-Remaining` after every page; a per-run ceiling (`RENAISS_MAX_CALLS`, default 1,500) that stops paging and reports, so no backfill can spend the day's 10,000; `429` honours `Retry-After` once, then stops.
3. **Sales** (`src/lib/renaiss/sales.ts`, `scripts/warm-renaiss-sales.ts`, migration `supabase/migrations/20260930000001_renaiss_sales.sql`): a row store keyed on the feed's `id` (`{txHash}:{logIndex}`) with `block_number`, `sold_at`, `contract`, `token_id`, `seller`, `buyer`, `currency`, `price` (decimal string), `price_usd` (from `priceUsdCents`; USDT counted as USD the way USDC is everywhere else, said once in the migration header), `cert`, `grader`, `grade_raw`, `catalog_id`, `renaiss_item_id`, `card_name`, `set_name`, `set_code`, `card_number`, `year`, `language`, `image_url`, `raw` jsonb. `--backfill` from the oldest row; incremental from `from` = the newest stored `sold_at` minus one day (overlap is harmless, the id upserts); `--limit N` pages; `--dry-run` fetches and prints, writes nothing. `runWarmer("renaiss-sales", …)`, SLA 6 h, in the `core` batch beside the DYLI step, in the `--require` list.
4. **Cards** — the same run upserts one `cards` row per distinct token seen (id `rn-<tokenId>`, `platform` `renaiss`, `chain` `BNB Chain`, `source` `renaiss-api`, name, set, number, grade label composed as `<company> <numeric grade>` from `company` + `grade` through `parseGrade`, cert, year, language, image), so `readCardDims("renaiss")`, `readCardMeta` and the `/card/rn-<tokenId>` page all work, and `extractCardIdentity` gains its `renaiss` quirk: set from `setName` (fall back to `setCode`), number from `cardNumber`, language from the field rather than the name, edition from the name as today. Nothing else about the extractor changes.
5. **The panel leg.** `readSaleFeed` gains `readRenaissSales({ sinceMs })` from the row store (never the API on a request path), mapped to `NormalizedSale`; `tagPlatform("renaiss", …)` then keys every Renaiss sale to an identity through the `cards` rows above, so Renaiss slabs join the reference price, the grade ladders, "where it trades" and the index candidates on the next indices warm. Report the identity-key refusal counts (`identityKeyRefusal`) and the set strings `normalizeSetName` does not recognise (Japanese set names are expected to be the bulk; count them, do NOT add aliases here, that is the set-alias brief's tooling).
6. **Pulls** (`src/lib/renaiss/pulls.ts`, `scripts/warm-renaiss-pulls.ts`): `gacha_pulls` rows with `pull_id` = the feed's `id`, `platform_id` `renaiss`, `product_id` = `machineId`, `buyer`, `price_usd` from `pricePaid`, `prize_instance_id` = `rn-<tokenId>` once named (and its `cards` row upserted as in 4), `prize_canonical_id` = the identity key when the card resolves, `prize_value_usd` = `prizeValue` (the platform's stated value, labelled so wherever it is shown), `tx_hash` = `transaction`, `source` `renaiss-api`, `pulled_at`; `kind` `observed` rows are stored with `price_usd` null and never counted as spend. Incremental = cursor + a trailing 14-day re-read with `from`, so a prize named late updates its row. Same flags, same ceiling, `runWarmer("renaiss-pulls", …)`, SLA 6 h, core batch.
7. **Volumes.** `core-volume` gains a `renaiss` entry built from the two row stores (`stats24h`, `sales24h`, `gachaVol24Usd`, `gachaVol7Usd`, the way `fetchDyliLaneWindows` feeds DYLI's), so `hasSecondarySource` is true and the 24h and 7d figures on the board are Renaiss's own; `scripts/warm-metric-snapshots.ts` gains a Renaiss block: `volume_usd` and `trades` per day from sales, `gacha_volume_usd` per day from `checkout` pulls, COMPLETE days only (a day is complete when the newest stored row is past its end and the run reached the present; the newest day is a partial and is never published, INV-8). Post-labelling: resale is resale, pulls are "packs" (Renaiss's word; the Claw is Beezie's).
8. **Honest blanks.** No listings feed → floor and market cap "—" with the coverage note; no holders read → "—"; no payout wallets → economics net held with "no payout source"; the seller fee unknown → volume is buyer-paid price, said in the Sources copy the methodology page renders from the registry. The `methodology` Sources entry for Renaiss comes from `PLATFORM_SOURCES` like the others; write its legs truthfully.
9. **Tests** (`test:renaiss`): the row mappers on fixture rows from the saved samples (a linked sale, an unlinked sale, a named and an unnamed pull, an `observed` pull); grade composition for `10 Gem Mint`, `9 Mint`, `GEM MT 10`, CGC `10 Pristine`; the identity quirk on a Japanese-set row and an English-set row; the cursor and `from` overlap; the no-key exit; the call ceiling.
