# Executor WP — card art you can read: one art component, trimmed slabs, a preview on hover

Frontend executor, Varible. One PR fresh off `origin/main` (e.g. `feat/card-art-legibility`), pushed, opened against main, NO merging. Own worktree with the three symlinks; `--webpack`; NEXT_PUBLIC_SHELL_V2=true; tsc/eslint/build clean; truthful trailer.

## The problem, measured (2026-09-17, production)
Nobody can tell which card a row is from its picture. Card art is drawn by four unrelated paths and only one of them is legible:
- `CardThumb` (`src/components/CardThumb.tsx`): a 28–36px SQUARE with `object-cover`. A slab photo is 5:7 with the label on top, so the square crop shows the middle of the slab at 30px — the set page's Top sales (36px) and Cards (28px) tables, the identity page's slabs table (28px), the report (32px).
- Raw `<img>` in `IPTables.tsx` (30×42), `PlatformTables.tsx` and `IPTraitTables.tsx` (28×36), all `object-cover`.
- The identity header (`IdentityHeader.tsx`): a 72/88px 5:7 frame with `object-contain` of the raw photo. The card is roughly half the slab's height, so the card is ~45px tall. The character header (PR #142) copied it.
- `TopSalesPanel.tsx` (homepage tiles): the ONLY legible path. Its private `autoTrim(img)` reads the photo's pixels through the same-origin `/api/img` proxy, finds the slab's bounding box, and swaps in a tight crop, so every slab shows whole at the same size whatever the source's padding (Beezie centres a slab on a 2160² near-black field).

## The fix — one component, three sizes, one preview
1. **`src/lib/img/autoTrim.ts`** — lift `autoTrim` and its load-escalation (direct → `/api/img` proxied → plain, exactly as TopSalesPanel does it, with the same comments) out of `TopSalesPanel.tsx` into a hook `useTrimmedArt(src)` → `{ src, trimmed, onLoad, onError, imgProps }`. TopSalesPanel uses the hook; its behaviour does not change (screenshot before/after, pixel-identical tiles).
2. **`CardThumb` becomes portrait and trimmed.** Sizes are a `variant`, not a pixel prop: `row` (40×56, the whole trimmed slab, `object-contain`, the 5:7 frame with the existing border and `bg-bg-2`), `cell` (30×42 for dense tables), `hero` (a 5:7 frame at 144px wide, for the identity and character headers; the card page keeps its own 340px hero). The `fill` mode stays for TrendingCards. Every one of the four paths above renders through it: `SetTopSales`, `SetCardsTable`, `SlabsTable`, `ReportView` (`row`); `IPTables`, `PlatformTables`, `IPTraitTables` (`cell`); `IdentityHeader`, `CharacterHeader` (`hero`). Delete the raw `<img>`s. A dead or missing image keeps its frame (the neutral placeholder, as today).
3. **Preview on hover.** Every `row` and `cell` thumb gets `ArtPreview`: on pointer hover (and keyboard focus of the row's link), after 120ms, a 220px-wide 5:7 panel with the trimmed slab floats beside the thumb — rendered in a portal on `document.body`, `pointer-events: none`, clamped inside the viewport (flip to the left of the thumb near the right edge, never off the top or bottom), the card's name and grade chip under the art in the panel, closes on leave/blur/scroll. On touch (`(hover: none)`) there is no hover: a tap on the thumb opens the same panel centred, a second tap or a tap outside closes it, and the row's own link still navigates when the NAME is tapped. One panel at a time. No layout shift in the table (the panel is out of flow). Reduced motion: no fade.
4. **Headers.** Identity and character headers use the `hero` variant (144px wide). The header's text block keeps its position; on phones the frame is 96px wide. Measure the header height at 1440 before and after in the PR body.
5. **Honesty.** A trim that fails (pixels unreadable) falls back to the untrimmed photo with `object-contain` — never `object-cover` in a portrait frame — so a slab is never shown cut. The preview shows the same image the thumb shows.

## Constraints
No copy changes beyond the preview's name and grade (from the row's own data; the grade through `GradeChip`, the grade SSOT). No new colours. No new reads: the preview uses the image URL the row already has. Tables keep their row heights (a 56px thumb fits the two-line rows that exist today; report the rows whose height changed, if any). `autoTrim` runs once per image, cached by URL in a module map, so a table of 100 rows does not re-read 100 canvases on every hover.
