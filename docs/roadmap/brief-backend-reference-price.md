# Executor WP — the reference price, backend: one key, one price, one receipt

Backend executor, Varible. One PR fresh off `origin/main` (e.g. `feat/reference-price-backend`), pushed, opened against main, NO merging. Own worktree with the three symlinks; never write to production from an executor (`--out` modes, `SNAPSHOT_LOCAL_DIR`, `--dry-run`, and `--apply`-gated scripts only); tsc/eslint clean; truthful trailer. Design: bet 1 in `docs/roadmap/features-roadmap.md`. This is the bet every later one stands on, so the report matters as much as the code.

## What exists (build on it, do not re-derive)
- `src/lib/data/traits.ts` `extractCardIdentity` → `CardIdentityParts` and `identityKey(ip, parts)` = `ip | RAW set | RAW number | NAME | grade | edition | language`. `src/lib/card/setName.ts` `normalizeSetName` (the set SSOT; its header says the identity key deliberately does NOT use it — that changes here, with the before/after it asked for). `src/lib/card/identity.ts` `identitySlug` / `parseIdentitySlug` / `identityHref` (the URL SSOT; `numberSlug` writes `/` as `~`).
- `src/lib/data/salePanel.ts` `buildSalePanel` (rows carry `identity`), `src/lib/data/identityIndex.ts` (`monthlyIdentityPrices`, `identityIndex`, `IdentityIndexPoint.obs` = `[logReturn, weight][]` stripped into the blob's `stepObs`, INV-13), `scripts/warm-sale-panel.ts` (writes `price-index`, `sale-panel`, `identity-index`, `identity-slabs`, `character-rollups`; `--out` mode).
- `src/lib/data/identityDetail.ts` (`getIdentityDetail`, `fragments` = the same card keyed twice: 1,129 measured Sep 14; `indexMembership`), `src/lib/card/identityView.ts` `readFloor` (the floor rule), `src/app/api/v1/identity/[...slug]/route.ts` + `src/lib/api/v1.ts` (keyed, attributed envelope), `src/app/api/internal/*` (key-free, IP-rate-limited pattern), `scripts/backfill-card-identity-key.ts` (`--apply`-gated, gap-fill).

## Scope
1. **v4.2 — the identity re-key.** `identityKey` keys on the CANONICAL set (`normalizeSetName(set).key`, falling back to the raw set slug when the normaliser returns null so no identity is lost) and a NORMALISED number: one function `normalizeCardNumber` in `src/lib/card/cardNumber.ts` — trim, drop `#`, drop a `/total` denominator (`025/102` → `25`; the set already keys it), drop leading zeros of the leading digit run (`006` → `6`), keep letter prefixes with their digits' leading zeros dropped (`TG16` → `TG16`, `SV049` → `SV49`), upper-case. Name, grade, edition and language are unchanged. `identitySlug` derives from the SAME normalised parts, so one identity has one URL; `parseIdentitySlug` accepts the old forms and `canonicalIdentitySlug(slug)` names the canonical one, and `src/proxy.ts` 301s an old form to it (one URL per card is what bet 4 will index). Every consumer of the key follows automatically because none of them build it themselves — prove that with a grep in the report.
2. **The shadow build, before any cutover.** `scripts/warm-sale-panel.ts --out=<dir> --shadow-rekey` writes the price-index blob under BOTH keys from the same panel and a `rekey-report.json` + a Markdown table for the PR: per published entity per month, identities priced (old → new), the step and the level (old → new, delta in pp), the thin flag, months that publish under the new key and not the old (and the reverse); the fragment count (expect 1,129 → ~0) and the number of identities the number rule merges on its own; the 30 largest merges by sales with their raw set strings and numbers, so a FALSE merge (two different cards folded by the same canonical set, number, name and grade) can be seen — report how many you judge false and why; grade-premium pairs and character rollups before and after (counts). No production write.
3. **The cutover, in one release.** `scripts/backfill-card-identity-key.ts --rewrite` recomputes `cards.identity_key` and `identity_slug` for every row (not gap-fill), chunked, resumable, dry-run by default; the orchestrator runs it after the merge. The price-index blob gains `method: "v4.2"` and the warmer writes a `method-changes` snapshot (append-only): `{ version: "v4.2", date, summary, entities: [{ id, month, levelBefore, levelAfter, identitiesBefore, identitiesAfter }] }` from the shadow build, so the methodology page renders the before/after from data, never from typed copy. INV-7/8/11/12/13 run on the new blob; nothing publishes if a gate fails.
4. **Receipts in the blob.** `stepObs` carries, per published step, `[slug, logReturn, weight, priceFrom, priceTo, nFrom, nTo]` (today it is anonymous `[logReturn, weight]`), and `readIndexReceipts(entityId, monthTs)` in `src/lib/data/indexReceipts.ts` returns `{ entity, month, level, step, spansMonths, thin, estimator: "interpolated weighted median", identities: [...] sorted by weight, held: { reason } | null }` — the withheld months explain themselves from the gate that held them. Size: report the blob before and after (gz); if it crosses 2 MB, split receipts into their own snapshot the same way identity-slabs was split.
5. **The reference price.** `GET /api/v1/price/<slug>` (keyed, attributed envelope) and the key-free, CDN-cached (`s-maxage=1800`), CORS-open `GET /api/public/price/<slug>` for the chip and the badge, IP-rate-limited like the internal chart endpoints, both from `getIdentityDetail` (no new reads): `{ slug, canonical: true|false, name, ip, set, number, grade, edition, language, price: { month, priceUsd, n, thin } | null, lastSale: { ts, priceUsd, venue, cardId } | null, floor: { priceUsd, venue, plausible, reference } | null (the identity page's floor rule, never an unplausible ask as a floor), receipts: the last 10 sales [{ ts, priceUsd, venue, cardId }], method: "v4.2", asOf, attribution: { text: "Varible price", url: "https://varible.rarible.com/i/<slug>" } }`. Unknown slug → 404 in the envelope; an old-form slug → the canonical payload with `canonical: false` and the canonical slug.
6. **The badge.** `GET /api/public/price/<slug>/badge.svg?size=sm|md` — an SVG a venue can drop in an `<img>`: black ground, lime `VARIBLE`, the price, the month, the sale count (`$323 · Aug · 5 sales`); with no monthly price it says `last sale $255 · Sep 9` and with no sale `no sale yet · N slabs`; unknown slug → 404 (an embed must never show an invented number). System font stacks only (no external fonts in an `<img>` SVG), `Cache-Control: public, s-maxage=1800`, `Access-Control-Allow-Origin: *`. Two sizes measured in the report.
7. **Report in the PR body**: the shadow table (top 12 entities × last 6 months), the merge review (30 largest, the false-merge count), fragments before/after, grade-premium and character counts before/after, the consumer grep, endpoint timings cold and warm for `pokemon/151/6/charizard-ex/psa-10` and one thin identity, both badge sizes as images, blob sizes, and the exact cutover commands for the orchestrator in order.
