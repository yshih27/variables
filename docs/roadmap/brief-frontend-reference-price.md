## The surfaces
1. **The price chip** — `/embed/price/<slug>`: a page with no shell, sized to its content (≤ 320×96 at `sm`, ≤ 420×120 at `md`), dark by default and `?theme=light`, from the public price endpoint: card name and grade chip, `Varible price $323 · Aug · 5 sales`, `last $255 · Collector Crypt · Sep 9`, and a `Varible ↗` mark linking to the identity page. No price this month → `no price this month · last sale $255`; no sale → `no sale yet · 51 slabs`; unknown slug → the 404. It is the thing a venue pastes, so it must be right at rest: no loading state, no layout shift, the numbers server-rendered, revalidate 30 min.
2. **"Get the chip"** on the identity page — a third action beside CSV and Share: a sheet with the iframe snippet, the badge snippet (`<a href="…/i/<slug>"><img src="…/badge.svg" alt="Varible price"></a>`), the API URL, and a live preview of both sizes of the badge and the chip; every snippet copies with one click and says "Copied". Attribution is part of the snippet, not optional.
3. **Receipts** — `/index/<entity>/<month>` (e.g. `/index/market/2026-08`, `/index/pokemon/2026-08`, `/index/set/pokemon-151/2026-08`): header (entity name from the naming SSOT, the month, `method v4.2`), KPI strip (level · step with `spans N months` when it does · identities in the step · thin flag), then ONE table — every identity in the step: name (link to its page), grade chip, price from → to, n from / n to, weight, return; sorted by weight; top 15 + "Show all" (the machines control). A withheld month renders the same header with the gate's reason in place of the table. Every published point on every index chart (Index Studio, the set, grade and IP index charts, the identity page's membership line) gets `receipts →` in its tooltip or under the chart's foot, so no index number on the site is more than one click from the identities behind it.
4. **The method line** — on every index chart, one receipt line under the foot: `method v4.2 since <date> · identities keyed on canonical set and number · what changed →` linking to the methodology page, rendered from the `method-changes` snapshot (date and version from data). The methodology page gains a "Method changes" section that renders the snapshot's before/after table (entity · month · level before → after · identities before → after); when the snapshot has no entries the section is absent, never a placeholder.
5. **Canonical URLs** — verify the 301 from an old-form slug (`…/006/…`, `…/25~102/…`) to the canonical one lands on the page with no double redirect; the `Get the chip` sheet always emits the canonical slug.

## Constraints
readMe ≤ 12 words and mode-true; no new colours (the chip and badge use the brand pair; grade colours are GradeChip's); zero new reads beyond the public price endpoint, `readIndexReceipts` and the `method-changes` snapshot; §7 where a pair appears; mobile: the receipts table scrolls inside its own container, the chip is fixed-size by design. No number is typed: the chip, the badge previews, the method line and the methodology table all come from data.
